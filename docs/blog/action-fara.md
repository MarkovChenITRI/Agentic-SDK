# 用 Fara 看懂畫面並操作電腦

!!! info "整合設計中"
    本文說明預定的 Fara 整合方式。實際部署指令、映像、吞吐量和安全測試結果尚未建立，文中不將它們描述成現有服務。

固定網頁定位方式很容易在版面或內容改變時失效。Fara 1.5 是視覺電腦操作模型：它根據任務、畫面與先前操作，產生單一步驟的滑鼠、鍵盤、捲動或搜尋操作。

此設計讓 AI Hub 將 Fara 部署成模型卡與推論服務，再由 Agentic SDK 的 Action 和 Reflect 模組控制操作次序、操作上限與人工確認。Fara 是模型卡候選項目，與 Letta 或 MatrAIx 的角色不同。

## 將 Fara 看懂畫面與操作電腦的能力做成模型卡

模型卡預定記錄 Fara 的版本、權重精度、vLLM 執行環境、CUDA 目標、內容長度、畫面輸入、單一步驟操作輸出、授權條件與研究預覽限制。模型卡是部署與相容性的依據。

## 在 A100 上部署可透過 OpenAI SDK 使用的 Fara 推論服務

預定部署路徑為 Fara 權重、vLLM、`NC24ads_A100_v4 VM`，再提供版本化端點與 `api_key`、`base_url`、`model` 設定。Fara 官方已公開 vLLM 與 OpenAI 相容服務的自架方式；實際部署參數及效能資料仍需在部署後記錄。

## 讓 Action 逐步執行 Fara 產生的操作

預定的 `FaraComputerUseAction` 會將任務、先前操作與畫面傳給模型服務，一次取得一個操作並記錄結果。瀏覽器控制器負責擷取畫面與執行點擊、輸入、按鍵或捲動；`FaraReflect` 檢查座標、回傳格式、頁面是否前進、操作上限與人工確認條件。

## 從模型卡匯出可直接用在工作流程的 Fara 設定

目標設定包含模型卡版本、A100 端點、Fara 模型、隔離測試環境與操作政策。應用程式將 Fara 的 Action 和 Reflect 模組放進 `Workflow` 後即可使用；這是待實作的設定輸出，不是現有入口網站功能。

## 用操作記錄確認 Fara 是否部署成功

驗證應在可重置的測試網站進行，檢查端點、點擊、輸入、捲動、錯誤座標、人工確認、逾時、操作上限與最後的網頁內容。每次測試都需保存畫面與操作記錄，才能追查模型、控制器和安全限制的行為。

## 讓工作流程在安全限制下操作電腦

完成整合後，開發者可選擇 Fara 模型卡並在工作流程中加入受控的視覺操作。AI Hub 也可在模型卡中管理電腦操作所需的輸入、輸出與安全欄位。
