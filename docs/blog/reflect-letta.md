# 用 Letta 將對話整理成可保存的長期記憶

!!! info "整合設計中"
    本文整理 Letta 與 Agentic SDK 的預定整合方式。AI Hub 尚未提供可直接產生此設定的產品功能，文中不把設計當成已驗證的使用經驗。

長對話會逐漸超過模型一次可讀取的內容長度。Letta 延續 MemGPT 的記憶管理做法，將可長期保留的內容與當前對話分開處理；Agentic SDK 的 Reflect 模組則可以依回覆與證據決定記憶是否需要更新。

這個設計中，AI Hub 提供文字或嵌入模型的模型卡與推論服務，Letta 負責保存及找回記憶，Agentic SDK 將它們組合進同一條工作流程。Letta 是記憶服務，不是模型卡。

## 用 Letta 將長期記憶整理成摘要並保存

模型卡記錄文字或嵌入模型、執行環境與部署條件。Letta 使用這些模型服務來管理核心記憶、長期記憶，以及找回過去對話的內容。

部署資料預定保存模型卡版本、模型名稱、執行環境、端點網址、Letta 版本、記憶儲存位置與憑證參照。實際使用的 Letta 用戶端版本和向量儲存方式必須在部署時確認。

## 讓記憶服務使用 OpenAI 相容的模型服務

Agentic SDK 的模型節點以 `api_key`、`base_url` 與 `model` 連到 OpenAI 相容的模型服務。記憶服務與工作流程可共用這組設定，因此應用程式不必為特定硬體或供應商另外撰寫連線邏輯。

## 由 Reflect 決定何時寫入與找回記憶

預定的 `LettaReflect` 與 `LettaPersistentMemory` 會根據回覆結果、可用證據與寫入結果，決定是否整理摘要、保存內容、找回記憶或明確回報失敗。這個設計對應 SDK 的 `PersistentMemory`、`WorkflowState`、`ContextEntry` 與 `ModuleOutput` 公開介面。

## 匯出可直接用在工作流程的記憶設定

目標是從模型卡的部署記錄產生版本化設定，內容包含模型服務連線、Letta 連線與記憶命名空間。應用程式讀取設定後即可附加到 `Workflow`；這是待實作的產品能力。

## 確認長期記憶能正確寫入與找回

驗證時需檢查模型服務是否可用、Letta 是否能寫入及找回長期記憶、跨對話重新建立是否正確，以及空結果、錯誤端點和錯誤憑證是否能留下可理解的錯誤記錄。測試記錄需保存模型卡版本、執行環境、命令、測試資料與追蹤資料。

## 隨模型部署一併提供長期記憶

完成整合後，開發者可在工作流程中使用能保留來源脈絡的長期記憶。AI Hub 則可將記憶服務作為模型卡部署的伴隨服務一起交付。
