# 用 MatrAIx 的角色設定產生不同風格的回覆

!!! info "整合設計中"
    本文說明預定的 MatrAIx 整合方式。MatrAIx Persona 1M 是資料集，不是推論模型，也不是現有的 AI Hub 模型卡。

一般文字模型可以生成完整回覆，但不會自然帶入特定使用者的觀點、偏好或表達方式。MatrAIx Persona 1M 提供可供研究的角色設定資料；實際生成回覆的仍是部署在 A100 上的文字模型。

此設計讓 AI Hub 保存版本化的角色設定資料，Agentic SDK 的 Action 只選用符合規範的設定，再將其放進模型提示內容。角色設定會影響語氣與偏好取捨，不會取代系統安全規則或檢索到的事實。

## 用 MatrAIx 的角色設定（Persona）資料決定回覆方向

Persona 1M 預定作為文字模型卡旁的版本化資料資產。部署資料需要保存資料集版本、授權條件、可用欄位清單、角色識別碼與資料來源分類。

敏感欄位和模仿真實人物的設定不得使用；篩選與選用規則是整合交付的一部分。

## 讓加速文字模型依角色設定產生回覆

部署在 A100 上的文字模型，以 `api_key`、`base_url` 與 `model` 提供回覆。角色設定只改變受控的提示內容，不改變模型權重，也不改寫從資料來源找到的事實。實作時仍需由 AI Hub 選擇實際可用的文字模型卡。

## 讓 Action 用角色設定引導模型回覆

預定的 `MatrAIxPersonaAction` 會合併使用者任務、找到的資料與已核准的角色設定。系統安全規則與資料事實優先，角色設定只影響語氣與偏好。此模組會獨立實作，避免依賴 `GenerativeAction` 的內部訊息組裝；Reflect 會檢查敏感欄位外洩、角色特徵呈現與事實是否正確。

## 匯出可重現角色設定的部署設定

目標部署設定包含文字模型卡版本、A100 端點、角色資料版本、欄位結構、可用欄位清單與選擇種子值，並可直接附加到 `Workflow`。這是待實作的 AI Hub 能力。

## 用版本資料與回覆記錄確認角色設定是否生效

驗證應檢查授權測試資料、模型服務輸出、重複選擇的結果、特徵是否正確呈現或排除、事實是否維持一致，以及禁止欄位和不確定回答是否符合規則。

## 讓同一個加速端點支援不同角色的回覆

完成整合後，開發者可用同一個加速文字模型進行可重現的角色回覆實驗。AI Hub 可管理角色資料資產，SDK 則可提供 `PersonaProvider` 與部署設定載入工具。
