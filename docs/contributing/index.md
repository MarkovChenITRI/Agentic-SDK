# 加入貢獻

這一頁帶著一個團隊從「想參與」走到「第一次貢獻併入」，逐步列出每一步做什麼、
產出什麼。適用於工研院內部其他單位，以及外部的合作團隊。

## 涵蓋內容

第一節說明為什麼歸屬要先定。第二節到第六節是五個步驟，前三步由維護者完成，
後兩步由貢獻的團隊執行。第七節列出五份紀錄各自在什麼時候更新。

## 為什麼歸屬要先定

本專案的技術屬工業技術研究院，商業使用需另循技術移轉取得授權。技轉作業要
界定移轉標的涵蓋哪些程式碼，因此每一段程式碼屬於哪個單位、由誰貢獻，必須是
可查的紀錄，不能靠事後翻提交歷史推斷。

歸屬在寫程式之前定好還有一個實務理由：第一個 Pull Request 送到時，
系統要知道該請誰審查。

## 第一步：開一張加入申請

新單位在 [Issues](https://github.com/R300-AI/Agentic-SDK/issues/new/choose)
選「新單位加入貢獻」，表單有七個欄位，五個必填。

| 欄位 | 填什麼 |
| --- | --- |
| 單位全名 | 寫到組，例如「工業技術研究院 機械與機電系統研究所 機器人技術組」 |
| 單位簡稱 | 表格裡使用的短稱，例如「Q 組」 |
| 貢獻人 | 一行一位，`GitHub 帳號　姓名　單位配發信箱` |
| 預計貢獻的功能 | 一到三句 |
| 預計涵蓋的路徑 | 一行一條，可用萬用字元；未定時填「待第一個 PR 後補」 |
| 授權確認 | 兩項核取方塊，勾了才能送出 |

貢獻人的信箱要與該 GitHub 帳號上的信箱一致，貢獻者圖表才算得到那個人。
建議填單位配發的信箱而非 GitHub 的 noreply 位址，該次提交的隸屬單位因而
直接留在歷史裡。

授權確認的第二項是技轉標的能否涵蓋該單位程式碼的依據。單位無法同意時，
在 issue 裡說明，由維護者與技轉單位個案處理。

## 第二步：加為協作者

維護者在 Settings → Collaborators 逐一加入申請單上的帳號，角色給 Write。
本專案的權限只到單一 repo，不使用組織層級的 team，所以審查權以個人帳號為單位。

角色分三階，新單位從 Write 開始。

| 角色 | 能做什麼 | 什麼時候給 |
| --- | --- | --- |
| Triage | 分類 issue、標籤 | 只協助議題管理時 |
| Write | 推分支、送 PR、審查 | 新單位加入時 |
| Maintain | 改 repo 設定、管理協作者 | 持續審查一段時間之後 |

## 第三步：設定審查路徑

維護者把帳號與路徑寫進 `.github/CODEOWNERS`，一行一條路徑，多人以空白分隔。

```
/agentic_sdk/vision/    @account1 @account2
```

被列的帳號必須先完成第二步，否則 GitHub 不會發出審查請求，而且不會有任何
錯誤訊息。設定完成後，動到該路徑的 Pull Request 會自動請這些人審查。

## 第四步：送出第一個 Pull Request

從 `main` 開分支，實作功能，送出 Pull Request。模板的檢查清單列出這一次要
更新哪些紀錄，逐項確認。

| 情況 | 要更新 |
| --- | --- |
| 一定會發生 | 提交訊息帶 `Co-authored-by:` 尾標 |
| 首次貢獻 | `CONTRIBUTORS.md` 的貢獻人表與單位表、`CITATION.cff` 的 authors |
| 貢獻一整塊新功能 | `REUSE.toml` 新增一個 `[[annotations]]` 區塊 |
| 依賴有增減 | 執行 `python scripts/generate_third_party_notices.py` |

零星修改既有檔案不需要動 `REUSE.toml`，該檔案的歸屬不因此改變。

## 第五步：審查與合併

CODEOWNERS 指派的審查者通過後即可合併。CI 另外檢查兩件事，任一項失敗都會
擋下合併。

| 檢查 | 失敗代表 |
| --- | --- |
| `generate_third_party_notices.py --check` | 依賴變了但授權清單沒重新產生 |
| `verify_ownership_paths.py` | `REUSE.toml` 的路徑指不到實際檔案 |

合併之後，第一步那張 issue 關閉，它本身就是該單位加入時的憑據。
README 的貢獻者頭像列會在下次重新產生時長出新頭像。

## 五份紀錄的分工

同一件事只記在一處，各自的粒度與更新時機不同。

| 紀錄 | 粒度 | 什麼時候更新 | 誰更新 |
| --- | --- | --- | --- |
| 提交的 `Co-authored-by:` 尾標 | 個人、逐次提交 | 每一次提交 | 提交者 |
| `CONTRIBUTORS.md` 貢獻人表 | 人 × 單位 × 期間 | 新貢獻人，或既有貢獻人換單位 | 送 PR 的人 |
| `CONTRIBUTORS.md` 單位表 | 單位、功能範疇 | 新單位，或既有單位範疇擴大 | 送 PR 的人 |
| `CITATION.cff` | 引用當下的作者與隸屬 | 新單位首次貢獻 | 送 PR 的人 |
| `REUSE.toml` | 路徑、著作權歸屬 | 新功能整塊歸某單位，或路徑搬移 | 送 PR 的人 |
| `.github/CODEOWNERS` | 路徑、審查責任 | 某單位開始負責一段路徑 | 維護者 |

換部門時在貢獻人表新增一列填新單位與起始月份，舊列補上結束月份但不改寫內容。
那段期間的貢獻歸屬於當時的單位，技轉標的依此判讀，事後改寫等於追溯變更歸屬。
