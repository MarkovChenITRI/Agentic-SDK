# 09: 設定改變時要不要清空對話歷史

**What to build:** 使用者改了 agent 的設定之後，Runner 裡既有的對話歷史應該保留還是清空。目前沒有任何處理。

**Blocked by:** 無，可立即開始

**Status:** wontfix

- [x] 已評估：不做

## Comments

**為什麼會有這張票：** 03 會移除一個從來不做事的 fingerprint——它在載入時重算一次，把存起來的舊值丟掉，兩者從來沒有比對過。它唯一的效果是強迫四個呼叫點傳入 Python 文字。

那段程式碼的存在暗示有人想過這個功能，但沒有做完。要不要真的做，是一個產品決定，不是重構的一部分，所以刻意不塞進 03。

**評估時要回答的：** 使用者改了設定之後看到舊對話，這是預期行為還是錯誤？如果要清空，是全部清掉還是只標記？

## 決定（2026-09-02）：保留對話，不做這個功能

使用者改了設定之後，既有的對話歷史原樣保留。系統不清空、不提示、不比對。

**理由：** 使用者改設定的時候正在任務中。因為改了一個檢索選項就把對話抹掉，是很大的驚嚇，而且不可復原。相對地，「舊回覆是舊規則產生的」這件事的代價小得多——它只是讓行為看起來不太一致，不會弄丟任何東西。

**這也解釋了票 03 為什麼刪掉 `workflow_fingerprint` 是對的。** 那段程式碼會算出指紋、存起來、然後從不比對。它看起來像是有人想做這個功能但沒做完。現在確認了：不是沒做完，是不該做。

**如果之後改變主意**，票 09 的歷史記錄了兩個替代方案：在對話上方顯示一行過期提示加「重新開始」按鈕（不刪任何東西），或是自動清空。前者需要把 fingerprint 加回來並且真的拿來比對。
