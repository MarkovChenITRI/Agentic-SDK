# 04: 不管哪裡出問題，Agent 都只說「暫時無法產生回覆。」

**What to build:** 執行失敗時，使用者看得出缺什麼、下一步該做什麼。

**Blocked by:** 無，可立即開始

**Status:** done

- [x] 缺模型端點綁定時，說出缺的是哪一個角色
- [x] 語意檢索沒有可用知識來源時，說要上傳檔案
- [x] 互動元件沒有 API 契約時，說要設定契約
- [x] 其餘未預期的例外維持通用訊息，但 `detail` 帶上例外型別
- [x] 每一種訊息各有一個測試

## 使用者遭遇的事

三種完全不同的情況，畫面上一模一樣：

```
缺模型綁定        → 暫時無法產生回覆。   detail: null
語意檢索沒上傳檔案 → 暫時無法產生回覆。   detail: null
互動元件沒設契約   → 暫時無法產生回覆。   detail: null
```

使用者沒有任何線索可以自救，只能猜。

## 這張票不能取代票 01、02、03

它讓已經知道的失敗原因說出來。真正的修法是讓那些失敗不要發生——票 03 讓 Builder 一開始就知道少了什麼，票 01 和 02 修掉行為本身的錯。

但即使那三張都修好，還是會有失敗，而使用者仍然需要知道原因。

## 一個已經對的部分

`MissingEndpointCredentials` 有自己的分支且訊息具體。`MissingEndpointBinding` 沒有，會落進通用分支——票 03 的失敗就是這樣被吞掉的。

## 完成記錄

三種原因現在各有各的訊息：缺模型綁定會說出是哪一個角色、語意檢索沒上傳文件會說要上傳、互動元件沒設契約會說要補契約。其餘未預期的例外維持通用訊息，但 `detail` 帶上例外型別，不再是 `null`。

`MissingEndpointBinding` 原本會落進通用分支被吞掉，現在有自己的處理。

**票 05 讓這張票的第一個情境變罕見。** 純查表 agent 不再需要綁定，所以最常見的「缺綁定」失敗消失了。訊息仍然需要，因為使用者選了需要模型的輸出格式時還是會遇到。
