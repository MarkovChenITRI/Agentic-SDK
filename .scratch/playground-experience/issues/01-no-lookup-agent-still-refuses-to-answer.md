# 01: 選了「不需要查資料」，Agent 還是說沒有足夠資料

**What to build:** 使用者在 Q3 選「不需要查資料」之後，Agent 會直接回答問題，而不是要求使用者提供文件。

**Blocked by:** 無，可立即開始

**Status:** done

- [x] 沒有配置檢索來源時，Action 的預設回覆規範不再要求「只根據 retrieved_context 回答」
- [x] 有配置檢索來源時，維持現在的行為（依檢索內容回答、沒查到就說沒查到）
- [x] 使用者自己填寫回覆規範時，仍然完全取代預設值
- [x] 三種情況各有一個測試

## 使用者遭遇的事

目的：做一個單純聊天的助理。Builder 五題照順序回答，Q3 選「不需要查資料」。

```
使用者 > 用一句話說明什麼是保固。
Agent  > 目前沒有足夠的資料來為您說明「保固」的定義，請提供相關產品文件、
         合約條款或保固政策內容，我才能針對你的情境給出準確解釋。
```

使用者明確說了不需要查資料，Agent 卻因為沒有檢索內容而拒絕回答。

## 原因

`GenerativeAction` 的 `DEFAULT_SYSTEM_PROMPT` 寫死了：

```
「你是 Agentic SDK 的 Action 模組。請只根據 retrieved_context 回答使用者；
  ⋯如果 retrieved_context 沒有足夠資料，請明確說沒有足夠資料。」
```

不論 Q3 選什麼，這段都一樣。實測 `retrieve_policy` 為 `none` 或 `keyword` 時，`action_prompt` 都是 `None`，代表兩者都落到這段預設值。

## 這件事有救，但使用者不會知道

Q4 有一個「回覆規範」欄位。填了就正常：

```
填入「你是一個親切的通用助理，請直接依常識回答使用者的問題。」之後 ——
Agent > 保固是製造商或賣家在一段約定期間內，保證產品若出現非人為的瑕疵或
        故障，即負責免費維修或更換的售後服務承諾。
```

但沒有任何地方提示要填。第一次使用的人得到的是一個看起來壞掉的助理。

## 為什麼這張票排第一

「聊天助理」是這個產品最基本的一種 agent。現在它的預設行為是壞的，而使用者沒有線索。

## 完成記錄

修在 SDK 層，所以所有使用者受益，不只 Playground。`GenerativeAction` 不再有單一的預設 prompt，改成每一輪依實際情況挑：這一輪有檢索到東西就照舊「只根據 retrieved_context 回答」，沒檢索到就開放回答但要求不確定時說明不確定。呼叫方自己傳 `system_prompt` 時，兩個預設都不套用。

`ToolCallAction` 一併處理——它原本共用同一個寫死的預設，互動元件的 agent 會有一樣的問題。

**沒有讓 Playground 去判斷該用哪段 prompt。** 那樣 Playground 就得知道 prompt 的內容，而 SDK 的預設對其他使用者仍然是壞的。條件放在模組自己身上，因為只有它知道這一輪到底有沒有檢索內容。
