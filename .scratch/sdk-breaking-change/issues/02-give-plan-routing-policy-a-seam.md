# 02: 讓 Plan 的路由政策有接縫

**What to build:** Plan 模組問模型下一步要查資料還是直接回答，然後用一份內建的中文零售關鍵字表推翻模型的答案。這份表寫在通用 SDK 裡，改它就得改 SDK。改成由呼叫方提供這條規則。

**Blocked by:** sdk-breaking-change/01

**Status:** needs-info

- [ ] 待設計

## Comments

**缺的資訊：** 這張票需要自己的 `/grilling`，主要決定政策介面的形狀，以及 SDK 要不要附一個預設政策。

**已知事實一：** 這份關鍵字表包含試穿、門市、取貨、調貨、庫存、現貨、展示品、品號、遊樂場。它是這個套件裡改動最頻繁的檔案之一，因為每個新案例都是一次編輯字面值。

**已知事實二：** 啟用這個覆寫的條件，是對模組自己的 system prompt 做子字串比對。所以傳入自訂 system prompt 會同時廢掉 retrieve 說明與整個覆寫機制，沒有錯誤訊息。反過來，一個剛好含有那個英文片語的 prompt 會啟用呼叫方從沒要求過的中文關鍵字表。這個組合目前沒有測試。

**已知事實三：** 專案的發布衛生測試禁止個案詞彙出現在 SDK 裡，但它的黑名單沒有涵蓋上面那九個詞，所以測試是綠的。設計時要一併決定黑名單怎麼補。

**完成之後：** 發布 0.2.0，變更紀錄寫清楚改了什麼。
