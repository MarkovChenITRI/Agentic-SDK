# 01: 用講的問問題

**What to build:** 一個 SDK 使用者可以宣告 `Workflow(perceive=VoiceTextPerceive(...))`，對著麥克風講一個問題，得到文字回答。安靜的時候什麼都不會發生。

**Blocked by:** 無，可立即開始

**Status:** ready-for-agent

- [ ] `VoiceTextPerceive` 佔 perceive 角色，宣告形狀與其他模組一致（三件式端點參數）
- [ ] 音訊傳輸接縫定義好，**輸入與輸出兩個方向都在這張確立**，後續模組直接用
- [ ] 傳輸參數是選用的：不傳就用端點參數建預設實作，README 範例不出現它
- [ ] 假傳輸能驅動整條流程，測試不需要網路也不需要憑證
- [ ] 靜音不上傳；有聲音才上傳；音量下降後多送一段避免切掉句尾
- [ ] 門檻可調

## 為什麼靜音過濾在這張而不是最佳化

實測 3 秒純靜音：計費 30 audio tokens（與 3 秒語音相同），而且被辨識成「这里」——沒有人說過的字。不過濾的話，安靜的房間會持續產生假輸入。這是正確性，不是省錢。

## 這張為什麼把接縫和模組綁在一起

單獨交付一個介面沒有東西可以驗證。接縫要靠第一個真實使用者才知道形狀對不對。
